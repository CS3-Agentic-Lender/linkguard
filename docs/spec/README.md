# Project specification: what is marked

Source: [agile-processes-project-specification.docx](agile-processes-project-specification.docx) (COMP7039 Agile Processes, 50% of the module mark). The dates in the original are from the previous year and are wrong for us; use the dates the lecturer gives this year.

## Rules that shape how we work

- Marks are **individual**. Points are lost for low attendance, incomplete tasks and poor communication.
- Workload must be balanced across the four members.
- Three sprints, each with a **different Scrum Master**: Sprint 1 Data Input, Sprint 2 Data Visualisation, Sprint 3 Knowledge Extraction.
- Each sprint has a planning meeting (goal + sprint log), standups with a burndown chart, and a retrospective with notes.
- The spec names the lecturer as Product Owner. Inside the team, the PO role rotates too (see [docs/sprints/README.md](../sprints/README.md)); bring backlog priorities to the lecturer for approval in the lab.
- Two submissions: an **interim report** after Sprint 2 and a **final report** after Sprint 3, then a group presentation.
- No marks for code quality, but working code is required and must not block teammates.

## Rubric (what each weight means for us)

| Criterion | Weight | What we must show |
|---|---|---|
| Project definition and objectives | 5 | Clear definition, SMART objectives |
| Team communication | 15 | Attend and contribute to every sprint meeting; positive interaction; attendance records and chat evidence |
| Product backlog and user stories | 20 | Every story has tasks, **points, priority and acceptance criteria** |
| Sprint artifacts | 20 | Correct burndown charts, useful meeting notes, a clear sprint goal that the stories comply with |
| DevOps | 15 | Repo and CI/CD **operational and documented**, with clear error messages on failure. Today we only have the secret scan; add build and test jobs |
| Implementation | 15 | Deliver all allocated story points; objectives evaluated; **testing code present** |
| Presentation | 10 | Slides and handout showing contribution and innovation; answer every question |

## Minimum project components

1. **Importing data** (parsing a file or web form, with cleaning of empty or incorrect values).
2. **Data presentation and visualisation** (tables and/or charts).
3. **Knowledge extraction** (machine learning or an LLM producing intelligent results).
