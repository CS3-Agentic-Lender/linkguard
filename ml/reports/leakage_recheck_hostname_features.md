# Leakage recheck: the ten hostname features

Generated by `uv run python -m leakage.recheck` (run from `ml/`) from the cleaned file `phiusiil_cleaned.csv` (235,370 rows). Label 1 is phishing and 0 is legitimate.
The features come from the shared extractor through `ml/featureset/build.py`. Links were only read as text. None was opened.

## Single-feature accuracy

This reruns the single-feature check from section 2 of `ml/reports/leakage_report.md` on the ten hostname features. Each score is the accuracy of a one-split decision tree on that feature alone. It is 5-fold cross-validated and sorted high to low. A feature over 95% is marked YES.

It uses every cleaned row. That makes it a dataset audit that only flags features. Any choice of features is made in the feature ranking story, on training rows only.

A one-split tree learns only one threshold, so it has almost no room to memorise individual hosts. So folds that are not grouped by host can barely inflate its score. On this data the grouped and ungrouped scores differ by under one point.

This check only finds a column that gives the answer away on its own. It does not find leakage from the split or the pipeline. The shared host-grouped split and the Pipeline rule guard against those.
